# 连续安全距离与 SAFE_DISTANCE 串口说明

更新时间：2026-07-19

## 1. 现在项目到底有没有一直识别安全距离

有。

当前 Qt 工程在 `astra-rgbd` 模式下会持续打开 Astra RGB 与 Depth，并持续计算：

```text
arm_tip 与 face 的三维净距
```

也就是说，Jetson 端是一直在做双目/RGB-D 安全距离识别的。

但需要区分两件事：

```text
一直计算安全距离：是
一直通过串口发送 SAFE_DISTANCE：否
```

## 2. 当前正式串口流程

当前正式流程是一次性安全锁存流程：

```text
Qt 点击“开始”
→ Jetson 发送 WORKFLOW_CTRL START_MEASURE，action=0x01
→ RA6M5 运动到公共测距位
→ RA6M5 回 MEASURE_POSITION_READY
→ Jetson 阶段性发送 SAFE_DISTANCE
→ RA6M5 收到足够的新鲜有效 SAFE_DISTANCE 后锁存安全距离
→ RA6M5 回 DISTANCE_SAFE_LATCHED
→ Jetson 停止发送 SAFE_DISTANCE
→ 后续进入三视图采集、选择视图、末端定靶、点痣
```

锁存后，Jetson 不再继续发送 `SAFE_DISTANCE`。

## 3. SAFE_DISTANCE 帧本身有没有连续模式标志位

没有。

当前 `SAFE_DISTANCE` 帧结构是：

```text
TYPE    = 0x05
PAYLOAD = uint16 distance_mm + uint8 valid
```

也就是：

```text
distance_mm
valid
```

这里没有额外字段表示：

```text
continuous = 1
mode = continuous
```

所以不能只靠修改 `SAFE_DISTANCE` payload 让 RA6M5 知道“现在进入连续安全距离模式”。

## 4. 有没有预留连续安全距离方案

有，但还不是当前正式协议。

历史/未来提案中预留的是：

```text
WORKFLOW_CTRL action = 0x04
START_MEASURE_CONTINUOUS
```

它的设计意图是：

```text
Jetson 请求 RA6M5 进入连续安全距离模式
RA6M5 在锁存后仍持续消费 SAFE_DISTANCE
Jetson 后续每 100~200 ms 发送新的 SAFE_DISTANCE
```

但是当前正式 RA6M5 协议仍只接受：

```text
WORKFLOW_CTRL action=0x01  START_MEASURE
WORKFLOW_CTRL action=0x02  FINISH_RETURN_HOME
WORKFLOW_CTRL action=0x03  ABORT_HOLD
```

当前 `action=0x04` 仍属于未正式启用的未来提案。

如果 Jetson 现在发送：

```text
WORKFLOW_CTRL action=0x04
```

RA6M5 会按当前协议拒绝：

```text
COMMAND_ACK value=0
error=INVALID_PARAM
```

因此 Jetson 现在不能单方面打开连续 `SAFE_DISTANCE`。

## 5. 当前项目锁存后的连续安全保护是什么

当前项目锁存后虽然不再发送 `SAFE_DISTANCE`，但 Jetson 本地仍持续计算 RGB-D 安全距离。

当前本地连续守卫逻辑是：

```text
锁存后继续计算 arm_tip-face 三维净距
如果有效净距小于阈值，例如 120 mm
Jetson 发送 WORKFLOW_CTRL ABORT_HOLD
RA6M5 收到后关闭输出、中止运动并原地保持
```

也就是说，当前项目是：

```text
双目距离一直算
危险由 Jetson 本地判断
危险时发送 ABORT_HOLD
```

不是：

```text
全流程持续发送 SAFE_DISTANCE 给 RA6M5
```

## 6. 如果要改成 RA6M5 持续接收 SAFE_DISTANCE，需要双方怎么改

如果后续要做真正的“全流程连续安全距离”，建议正式启用：

```text
WORKFLOW_CTRL action=0x04
START_MEASURE_CONTINUOUS
```

RA6M5 需要实现以下语义：

1. 接受 `WORKFLOW_CTRL action=0x04`，并返回 `COMMAND_ACK ACCEPTED`。
2. 到达公共测距位后进入连续安全距离模式。
3. 初始阶段仍按当前规则使用多个有效 `SAFE_DISTANCE` 样本完成安全锁存。
4. 安全锁存后，HOME、三视图、选视图、定靶、输出阶段仍继续消费新的 `SAFE_DISTANCE`。
5. 每个有效 `SAFE_DISTANCE` 必须使用新的非零 `SEQ`。
6. 重复 `SEQ` 或重复 payload 不得刷新安全距离 freshness。
7. 如果连续一段时间没有收到新的有效 `SAFE_DISTANCE`，RA6M5 应进入安全状态。
8. 建议定义 `SAFE_DISTANCE_TIMEOUT`，例如错误码 `0x10`。
9. 如果收到 `valid=0` 或距离低于阈值，RA6M5 应立即关闭输出并进入安全保持/撤离逻辑。
10. Jetson 停止发送旧距离，不允许用旧样本伪装新鲜距离。

Jetson 需要实现：

1. 启动时发送 `WORKFLOW_CTRL action=0x04`。
2. RA6M5 接受后，锁存前后都按 `100~200 ms` 周期发送新的 `SAFE_DISTANCE`。
3. 只发送新鲜 RGB-D 结果；YOLO 过期、RGB/Depth 不同步、Depth 质量不足时不发送。
4. 每帧使用新的 SEQ。
5. 收到 RA6M5 的距离错误或超时状态后，停止自动流程并提示。

## 7. 当前不建议直接做的事情

当前不建议 Jetson 单方面做以下事情：

```text
1. 在正式 run_full_arm.sh 中加入 --continuous-safe-distance
2. 直接发送 WORKFLOW_CTRL action=0x04
3. 锁存后继续向 RA6M5 发送 SAFE_DISTANCE
4. 用 valid=0 周期刷存在感
5. 重发旧距离样本
```

原因是当前 RA6M5 正式协议还没有启用连续模式，单方面发送可能导致：

```text
INVALID_PARAM
时序错误
流程被 ABORT_HOLD
安全距离状态误判
```

## 8. 当前推荐结论

当前版本保持：

```text
开始阶段：SAFE_DISTANCE 发送给 RA6M5，用于安全锁存
锁存之后：Jetson 本地持续计算 RGB-D 安全距离
危险时：Jetson 发送 ABORT_HOLD
```

如果要升级成：

```text
锁存后也一直给 RA6M5 发送 SAFE_DISTANCE
```

必须先让 RA6M5 正式支持：

```text
WORKFLOW_CTRL action=0x04 START_MEASURE_CONTINUOUS
```

并共同确认超时、低距、valid=0、SEQ 去重、状态回传和安全停止语义。
